## 1. What Silver Trading System Does

A personal trading decision support system for precious metals ETFs. It implements a rule-based rotation strategy across silver and gold ETFs, with exponential position sizing based on conviction level and portfolio state.

**This is NOT an automated trading bot.** It generates recommendations and tracks decisions. Nick executes trades manually through his brokerage.

---

## 2. Core Concepts

| Concept | Description |
|---------|-------------|
| **Rotation** | Shifting capital between AGQ (2x silver), SLV (1x silver), and GLD (gold) based on market conditions |
| **Position Size** | Dollar amount allocated to each position, calculated via exponential curves |
| **Signal** | A rule-triggered recommendation to rotate, add, or trim a position |
| **Strategy** | A named set of rules that defines when to generate signals |
| **Trade Log** | Historical record of all recommendations and executed trades |

### ETFs Tracked

| ETF | Description | Risk Level |
|-----|-------------|------------|
| **AGQ** | ProShares Ultra Silver (2x leveraged) | High |
| **SLV** | iShares Silver Trust (1x) | Medium |
| **GLD** | SPDR Gold Trust | Lower (hedge) |
| **Cash** | No position | Lowest |

## 3. Key Features

### 3.1 Rotation Calculator
- Input: Current prices, current positions, strategy parameters
- Output: Recommended action (buy/sell/hold/rotate) with exact quantities
- Rules engine evaluates percentage thresholds to trigger rotations
- Percentage change thresholds are configurable per strategy

### 3.2 Exponential Position Sizing
- Position size scales exponentially with conviction level (1-10 scale)
- Curve parameters: base amount, growth rate, max position size
- Visualized as a chart so Nick can see the risk curve
- Respects portfolio-level max allocation limits

### 3.3 Strategy Visualization
- Chart showing current positions vs. recommended positions
- Historical performance of the strategy's recommendations
- Drawdown visualization
- Silver/gold ratio chart with signal overlays

### 3.4 Trade Tracking
- Log every recommendation (whether acted on or not)
- Log every actual trade execution (price, quantity, fees)
- Compare recommended vs. actual to measure discipline
- P&L tracking per position and total

### 3.5 Price Dashboard
- Current prices for AGQ, SLV, GLD
- Daily change, % change
- Silver/gold ratio
- Key levels (support/resistance from strategy rules)

## 6. Calculation Engine

### 6.1 Rotation Logic

The rotation engine is the core business logic. It lives in a pure function module with zero side effects.

```typescript
// Pure function — no database calls, no API calls
interface RotationInput {
  currentPositions: Position[]
  currentPrices: Record<ETF, number>
  strategy: StrategyParameters
  portfolioValue: number
}

interface RotationOutput {
  signals: Signal[]
  reasoning: string[]   // Human-readable explanation of each decision
  noAction?: string     // Why no trade is recommended (if applicable)
}

function calculateRotation(input: RotationInput): RotationOutput {
  // 1. Calculate % change from cost basis for each position
  // 2. Evaluate against strategy thresholds
  // 3. If threshold breached, generate signal
  // 4. Apply position sizing to recommended amounts
  // 5. Enforce max allocation limits
  // 6. Return signals with full reasoning
}
```

### 6.2 Position Sizing (Exponential Curve)

```typescript
// Amount = base * (growthRate ^ (conviction - 1))
// Capped at maxPosition
function calculatePositionSize(
  conviction: number,       // 1-10
  base: number,             // e.g., 1000
  growthRate: number,        // e.g., 1.5
  maxPosition: number       // e.g., 50000
): number {
  const raw = base * Math.pow(growthRate, conviction - 1)
  return Math.min(raw, maxPosition)
}

// Example with base=1000, rate=1.5:
// Conviction 1:  $1,000
// Conviction 3:  $2,250
// Conviction 5:  $5,063
// Conviction 7:  $11,391
// Conviction 10: $38,443
```

### 6.3 Isolation Rules

- Calculation functions are PURE. No imports from Supabase, no fetch calls.
- They live in `lib/calculations/` with 100% test coverage.
- Tests use hardcoded scenarios, not mock databases.
- If a calculation needs price data, it receives it as a parameter.

## 7. Price Data

### 7.1 Source

Prices come from a free API (Alpha Vantage, Yahoo Finance API, or similar). The app does NOT need real-time streaming — daily close prices are sufficient.

### 7.2 Refresh Strategy

- Manual refresh button on the dashboard.
- Optional: daily cron job via Vercel to snapshot closing prices.
- Price data cached in Supabase `price_history` table.
- No paid API subscriptions required for MVP.

### 7.3 Important Note

This tool does NOT execute trades automatically. It provides recommendations. Nick manually executes via his brokerage. The "trade log" feature is for recording what he actually did, not for automated execution.

## 11. Migration from Current HTML App

The current Silver Trading System is a standalone HTML application. Migration approach:

1. **Extract business logic first** — identify all calculation rules from the HTML/JS.
2. **Write tests for those rules** — test-driven migration.
3. **Build the new UI incrementally** — don't try to replicate the old UI exactly.
4. **Parallel run** — keep old app available until new one is verified.
5. **Data migration** — if there's existing trade history, write a one-time import script.
